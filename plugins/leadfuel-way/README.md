# leadfuel-way

The way every session works, as a Claude Code plugin. A skill is advice a session may forget;
the hooks in this plugin are the part that happens anyway.

**What it does**
- **Every session start** gets a `THE WAY` banner: its role (read from its title: conductor, router, or a desk lane), its model's handoff caps, and an instruction to load the right skill. No banner means the hooks are not live.
- **The handoff guard** measures the session's real context from its transcript and tells it to hand off at the cap for its model (Opus and Sonnet 300k soft / 450k hard; Haiku 120k / 150k). Past the soft cap, the **Stop hook** sends a session back to write the handoff once before it may end a turn.
- **A conductor or router may not edit inside a git checkout** (handoff notes and `.conductor/` state excepted). Work goes to desks. A session is a coordinator if its title starts with `CONDUCTOR` or `ROUTER` (upper case, whatever follows); ROUTER and CONDUCTOR are tiers, never desk lanes, so a desk's lane is one of the owner's desk lanes (NODE, DOORS, ...). Only the four edit tools are covered, not shell commands.
- **Desks are grouped by project** (owner, 2026-10-07; 0.1.8, reworded 0.1.9). A desk is titled `LANE · <project> part · n` (the lane, the project's name followed by the word `part`, then n; for example `INTELLIGENCE · world intel part · 3`) and filed in its project's sidebar group (`world intel`); the lane stays in the title, and CONDUCTOR and ROUTER keep their tier groups. The older titles (`LANE · <task id> n/m · topic`, `LANE · topic`, `ROUTER #N`, `CONDUCTOR · topic`) are still read by every hook, so sessions migrate one at a time. The `new-project` skill makes a project's group; nothing falls back to the lane's group.
- **No self-archive before a live successor.** `archive_session` on `self` is refused until the session has read its successor back with `list_sessions` / `get_session`, live in the right group. A project-form desk's group is its own, read with `get_session` on `self`.
- **No bulk moves.** A `move_sessions` call that names more than one session is refused: sessions move one at a time, never in bulk. The plugin itself never moves or retitles a session.
- **The test rule is taught in `way`, `desk` and `router`** (owner, 2026-10-11, card q354 A; 0.1.10): static gates plus the test files for what you changed, locally; the full suite once, in CI, on the exact head you merge; a full local bare `pytest` only when the test setup itself changes. No hook enforces it.
- **Starting a session with no click** (owner, 2026-10-13; 0.1.11). `start_session` is switched off for the owner's account and a `spawn_task` chip needs a click, so the `launch` skill starts a session by running a scheduled-task launch slot (`way-slot-01` to `way-slot-06`): `run_scheduled_task` returns the new session's id, `update_scheduled_task` swaps the brief and title between runs. Measured: it starts, retitles, takes a model change and a message, and can be archived from outside. It can never be filed in a sidebar group (the app refuses), and its routine's permission mode is the owner's to set to Bypass, once. The archive guard counts a successor launched into a slot by its `way-slot-NN` `scheduledTaskId` in place of a group. What was measured and what was taken on trust is in `docs/SLOT-LAUNCH.md`.
- **Ask the launcher** (owner, 2026-10-14, pick 264; 0.1.12; the fallback since 0.1.14). A scheduled-task run nobody has typed into cannot update or run a scheduled task, so a router or conductor launched into a slot and left alone cannot start its own successor. One standing regular session, the launcher, runs the launch steps for everyone: a session sends it a `LAUNCH-REQUEST`, it answers `LAUNCHED <id>`. The hook sends a slot-run router or conductor back once if it hands off without having asked (or armed a slot itself, 0.1.14). The design, the three measurements and the one paste that starts the launcher are in `docs/SLOT-LAUNCH.md`.
- **A session launches its own successor** (owner, 2026-10-14, to conductor 039: "yes make sure you can do this. auto create slots"; NODE~LAUNCH-BY-FIREAT; 0.1.14). The standing method of the `launch` skill: pick a free slot (or create `way-slot-NN` when none is free), write the successor's brief and the slot block into it, pin the model, and set a one-time `fireAt` about two minutes ahead with `update_scheduled_task`. The app starts the run by itself (no paste, no click, no launcher in the loop); the predecessor reads it back, sets effort and sends `GO`. `run_scheduled_task` is never used. It works from a regular session and from a slot run a person has typed into; a run nobody has typed into is refused by the app and falls back to the launcher. The 0.1.12 to 0.1.13 hook refused `update_scheduled_task` from a slot run, which blocked this; 0.1.14 refuses only `run_scheduled_task`, and the Stop gate accepts a `fireAt` call or a `LAUNCH-REQUEST`. What was measured and what is untested is in `docs/SLOT-LAUNCH.md`, "Measured 2026-10-14".
- **A click on a card wakes the asker** (owner's queued pick NODE~WAKE-ON-ANSWER; 0.1.13). The `wake` skill is one pass of a watcher run by a scheduled task (`wake-on-answer`, Haiku): it sends each answered, unrouted Router desk card to the session that asked (or to the live router), and records `DELIVERED` only when the message shows in that session's own transcript; queued or held is `HELD`, a failed send is `UNDELIVERED` with a durable note on the Build Board, and a pass that cannot see is `UNKNOWN`. Logic in `scripts/wake_on_answer.py`. The task is the owner's to switch on (and to set to Bypass, as the slots are).
- **Nested desks, archive when the whole task is done, sub-agents by default** (owner, 2026-10-31; 0.1.17; taught in `way` section 2b, `router`, `desk`, `handoff`, `conductor`; no hook enforces it). A desk a router opens with `start_session` is nested under it; a desk is archived when its whole task is done, not when its first PR opens, and the router closes finished desks before it opens more; sub-agents do the reading, the independent parts and the review. **Measured 2026-10-31 and 2026-11-01 UTC, and it changes how filing works:** all 17 nested sessions in the sidebar were in the same group as their opener (6 pairs ungrouped, 2 in a lane group; none opened by a router or conductor), `start_session` has no group parameter, and `move_sessions` refused to move a nested session alone ("nested sessions move with their parent"). So a nested desk is filed with its opener; for a router's desk that is **inferred**, not run, to be the router's group, not necessarily the project's. Whether a project's router should live in the project's group is an open question for the owner (Router desk card q1029); until it is answered, filing is unchanged and the title carries the project. The archive guard in the hook is unchanged: it proves a router's or conductor's successor only in the ROUTER or CONDUCTOR group. `start_session` is available in this app as of 2026-10-31 (`list_sessions` shows 17 sessions started with it), which the 0.1.11 line above recorded as switched off on 2026-10-13.
- **The wake pass works unattended** (owner, 2026-10-31: 'i shouldnt have to keep approving things'; 0.1.15). On 2026-10-31 every scheduled pass stopped at its own check because the routine runs in `auto` mode, 38 answered cards sat unrouted, and the one pass that ran in bypass tried to send 212 answers as a single 53.7 KB message and could not. Now `auto` is accepted (a send the app refuses is a result the judge records, not a reason to stop), a card is routed to the router its `asker` names by title (or that project's live successor) using the app's own session folder, an answer older than 48 hours is listed as stale and never sent, and one message carries at most 10 cards and 7,000 characters.
- **Eight skills**: `way` (every session), `handoff` (every tier), `conductor`, `router`, `desk`, `new-project`, `launch`, `wake`. Invoked as `leadfuel-way:<name>`.

**Install (owner step, once).** Installing writes `~/.claude/settings.json`, which sessions may not edit.
```
claude plugin marketplace add NOVAHGREYWOLF/leadfuel-core
claude plugin install leadfuel-way@leadfuel
```
The marketplace is this repo (`.claude-plugin/marketplace.json`, name `leadfuel`). Until this reaches the default branch, add a local checkout of the branch instead: `claude plugin marketplace add <path to the checkout>`. Start a fresh session afterwards: hooks load at session start.

**Prove it is live.**
```
python scripts/way_doctor.py          # LIVE only if every piece was seen working; UNKNOWN is never a pass
python scripts/way_pilot.py           # one small Haiku run with a low cap; needs `claude auth login` first
python scripts/way_caps.py set 40000 90000 --minutes 90   # force a low cap on every session, for a desktop pilot
python scripts/way_caps.py clear
```
- **The wake pass no longer guesses a router** (NODE~WAKE-NO-TARGET; 0.1.18). A card whose asker names a `ROUTER #N` that no live router has is no target (UNDELIVERED, with a Build Board note), not a send to `router/current`; an asker that is exactly one live session's title reaches that session. Measured 2026-11-01: 4 of 5 sends to idle routers were not picked up and none appeared in a target transcript.
- **A session that needs the owner posts its own card** (owner, 2026-10-31; NODE~POST-CARD; 0.1.19). `scripts/post_card.py` builds a valid Router desk `questions` document (the fields of the live cards, the asker's own session id as `asker_session`, option X always present, the default never X); the session writes it with ArtifactData `set`, and the wake pass carries the owner's click back to it. `desk` and `router` now say: a `NEEDS-NOVAH`, an `ASK` or an approval request is a card, never chat, never `AskUserQuestion`, never a chip that needs a click.
- **The wake pass also resumes sessions a usage limit stranded** (owner, 2026-10-31; NODE~RESUME-SWEEP; 0.1.20). `scripts/resume_sweep.py` reads the app's session store: an unarchived session whose `error` is a usage limit, whose last activity is no later than the error, whose reset time (parsed with zoneinfo from the error text) has passed, with no usage window at 100%, gets one message, `limit reset, keep going`: at most 8 a pass, inside the ten-send pause, 60-minute cooldown, three nudges per error. Launch slots count as sessions; any other routine's run does not. An unreadable reset time or usage file nudges nobody.
- **The Stop hook sends a session back once to post its card** (owner, 2026-11-01, card q9124 A; NODE~CARD-GATE; 0.1.21). When a turn that no person started (another session's message, a scheduled run, a task notice) ends on a `STATUS: NEEDS-NOVAH` or an `ASK:` line and no ArtifactData write to the Router desk `questions` collection happened in that turn, the Stop hook blocks once (never on the harness's retry, at most three times a session) with the instruction to post the card with `post_card.py`. A turn a person typed into, a turn that wrote a card, and a transcript the hook cannot read (unknown) are never blocked. `WAY_CARD_GATE=0` switches it off.
- **A router rewrites `router/current` on every rotation** (owner, 2026-11-01, card q9126 A; NODE~ROUTER-CURRENT; 0.1.22). The `router` skill's Rotate step 3 and Claim step 1 and the `handoff` skill now say what to write (`session_id`, `incarnation`, `predecessor`, `status`, `next_session_id`) and to pin the update with `if_version`; the new router reads it back. A stale pointer named a retired router while twelve project routers were asking.
- **A desk at its cap opens its own nested successor, and each task of a build gets its own sub-agent** (owner, 2026-11-01; NODE~WAY-DESK-SUCCESSOR; 0.1.23; taught in `way` section 2b and 5, `handoff`, `desk`, `router`, `launch`, `conductor`, `new-project`; no hook enforces it). In a session where building happens, each task goes to its own sub-agent (one brief per task, in parallel only when no task needs another's result and no two touch the same files); the session keeps the plan, the integration, the deciding checks, the pull request and the report, and a router's or conductor's sub-agents still only read. A desk at its cap with work left opens its successor itself with `start_session` (same lane and project, n advanced, titled at once), nested under it; **the successor archives the predecessor from inside its own first turn** once it is live and titled, the predecessor's handoff is pushed, nothing of it is unpushed and no owner decision is pending, and **the predecessor does not archive itself** when it has a nested successor. **The limit, stated next to the rule:** [read] in the app's rules for starting a session, as given to the session in its instructions (not in the tool schema), the app refuses `start_session` while the session is working on a message from another session, and `user_asked` needs the user's own words, so a desk whose turn its router's message drives cannot; then the router opens the successor nested under the router, beside the old desk (the 0.1.17 wording, now the fallback), else a launch slot, else the owner's paste prompt and the desk stays open. The successor reports to the router by `SendMessage` from its first turn (**inferred, not measured**). **Measured 2026-11-01 UTC, one successor case and one further case, not why:** the desk at n = 8 of a project's line has `parentSessionId` naming the n = 7 desk, which wrote a handoff note; in `list_sessions` the n = 7 desk is archived and the n = 8 desk is live and running (that the archive call came from inside the n = 8 desk's turn was reported, not shown by that state). A second desk (n = 6) has `startedBy` naming another desk, which shows a desk opening a nested desk, but it is named for a side task, so whether it was a successor at a cap is **not established**; neither is whether the cap was the reason for the n = 7 desk's successor, whether that turn was driven by the user's own words, or how a router hears from a nested successor. **Filing is decided:** Router desk card q1029 was answered B (owner, 2026-11-01): routers stay in the ROUTER group, nested desks land there, and the title carries the project; the 0.1.17 bullet above is the dated record of the question. Known mismatch, not fixed in this version: the banner and the hook expect a desk to be in its project's group. This removes three contradictions: "a desk never opens a desk" (a desk opens no desk for a task of its own; its own successor is the one exception), "the router opens its successor beside the old desk, not under it" (now the fallback), and `way` section 5's "only if you started the successor yourself do you archive yourself" (reversed for a nested successor). The `launch` skill no longer says `start_session` is switched off (it was on 2026-10-13 and is available again as of 2026-10-31). **The archive guard is unchanged and does not enforce this:** it guards only `archive_session` on `self`, never looks at who opened the successor, and does not guard an archive of another session, which is what lets the successor archive its predecessor.
- **The hook now allows for a desk nested in the ROUTER group, and its cap text agrees with the desk skill** (owner, 2026-11-01, card q1029 option B and the owner's "Yes, queue it" to NODE~WAY-NESTED-DESK-HOOK; 0.1.24). Three changes in `hooks/way_hook.py`. (1) The session-start banner no longer calls a nested desk misfiled: a desk its router opened with `start_session` is filed in the router's group and `move_sessions` refuses to move it, and the banner for an unfiled-looking session says it is computed before the opener titles it, so read `get_session` first. (2) `is_successor` recognises a nested desk's own nested successor in a tier group **only with an opener proof**: same tier group as the desk itself, a project-form title (`LANE · <project> part · n`) of the same lane and project with n advanced, and the row's `startedBy` or `parentSessionId` equal to the desk's own `sessionId`; an unknown own id or group, a missing, unreadable or conflicting opener, the older title forms and the 0.1.8 free-text part all refuse. (3) The context guard and the Stop hook no longer tell every session to "give the owner the one prompt for a fresh session": the text now follows the desk skill's four situations by role (a desk opens its nested successor with `start_session` in a turn the user's own words drive, else reports `STATUS: CONTINUING` and its router opens it; a router or conductor follows `handoff`; the paste prompt is the last resort and the session stays open), and a test reads the desk skill so the two cannot drift apart. **Not changed, and worth knowing:** the guard is still a floor, not the rule: a nested desk whose nested successor is live may self-archive (as it already could in a project group) although the skills say the successor archives it, and archiving a parent can archive its idle nested sessions; a router the conductor opens with `start_session` (CONDUCTOR group) is still not proven by the hook; `startedBy` and `parentSessionId` as plain id strings were read in earlier tool results on this machine, and that a desk's nested successor lands in the desk's own tier group is **inferred**, not run with the guard live.

**Switches (environment).** `SESSION_SOFT_TOKENS` / `SESSION_HARD_TOKENS` override the caps; `SESSION_GUARD_OFF=1` disables the guard and the Stop gate; `WAY_CARD_GATE=0` disables the card gate; `WAY_ENFORCE_ROLES=0` disables the coordinator edit rule, the background-agent rules and the bulk-move rule; `WAY_ARCHIVE_GUARD=0` disables the self-archive guard; `WAY_STATE_DIR` moves the per-session state (default: a `leadfuel-way` folder under the temp directory).

**Tests.** CI runs the full suite on every PR (workflow `test`, job `pytest`: a bare `pytest` from the repo root, which collects `plugins/`; see `pyproject.toml` for why). Locally, run the test files for what you changed, for example `pytest plugins/leadfuel-way/tests/test_plugin_layout.py`. A change to `pytest.ini`, the pytest config in `pyproject.toml`, a `conftest.py` or the test workflow still gets a full local bare `pytest` (0.1.10; owner, 2026-10-11, card q354 A).

The repo is public: this plugin carries ids, titles, status and PR numbers only.
